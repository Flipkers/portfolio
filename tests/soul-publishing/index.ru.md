### 2. Введение

a. Обзор, описание проблемы, резюме или абстракт

- Задача — создать систему, которая автоматически отслеживает использование музыки в видео TikTok у партнёрских авторов и считает выплаты по числу просмотров этих видео. Решение включает сбор данных о просмотрах, сопоставление с отчётом дистрибьютора о выручке и расчёт выплат авторам за месяц. Сейчас процесс ручной, он неэффективен и может приводить к ошибкам и задержкам. Цель — автоматизировать весь процесс, чтобы повысить точность и скорость.

b. Глоссарий или термины

- Использование музыки: когда автор TikTok выбирает трек для своего видео.
- TikTok API: API, который даёт доступ к данным видео TikTok.
- Автоматизация: процесс учёта и обработки использования видео и музыки без участия человека.
- Отчёт дистрибьютора: ежемесячный отчёт дистрибьютора с заработком по каждому треку, использованному в видео TikTok.
- Выплата автору: сумма, которую автор TikTok получает за просмотры своего видео с лицензионной музыкой.
- Доля выручки: часть выручки от просмотров видео, которая делится с авторами.

c. Контекст или фон

- **Почему задачу стоит решать:** ручной учёт использования музыки и расчёт выплат отнимают время и неэффективны. Автоматизация сэкономит время, снизит ошибки и даст авторам своевременные выплаты.
- **Откуда взялась задача: потребность упростить и автоматизировать учёт просмотров видео TikTok и связанных выплат появилась из-за ручного характера текущих процессов.**
- **Как задача влияет на пользователей и цели компании:** автоматизация повысит операционную эффективность, ускорит выплаты авторам и даст точные и прозрачные данные, что укрепит отношения с авторами и дистрибьютором.

d. Цели или продуктовые и технические требования

Продуктовые требования:

1) Автоматически считать, сколько видео TikTok использовали треки из нашей музыкальной библиотеки.

2) Считать просмотры этих видео по данным TikTok.

3) Сопоставлять эти данные с ежемесячным отчётом дистрибьютора о выручке, чтобы определить заработок каждого автора

4) Формировать точные выплаты авторам.

Технические требования

1) Интеграция с API TikTok для данных о видео и просмотрах.

2) Хранение данных, чтобы учитывать использования видео и считать выплаты

3) Алгоритм, который обрабатывает данные о просмотрах и сопоставляет их с заработком дистрибьютора.

e. Не-цели или вне скоупа

- Проектирование самого платёжного решения
- Расширение на другие платформы кроме TikTok

f. Будущие цели

- Расширить решение дополнительными данными: география, метрики вовлечения видео и т.д.

g. Допущения

- API TikTok будет давать надёжные данные о просмотрах и использовании.
- Дистрибьютор продолжит давать точные ежемесячные отчёты о выручке.
- Дистрибьютор сможет передавать информацию о музыке в виде music_id по API TikTok.

### **a. Текущее или существующее решение / дизайн**

- **Описание текущего решения**: сейчас учёт использования музыки и расчёт выплат делаются вручную и требуют сверки данных видео TikTok с отчётами дистрибьютора.
- **Плюсы и минусы**:
    - Плюсы: легко вести на маленьком масштабе.
    - Минусы: неэффективно, подвержено человеческим ошибкам, плохо масштабируется.

### **b. Предлагаемое решение / дизайн**

- **Внешние компоненты**: TikTok API (данные видео и просмотры), отчёт дистрибьютора о выручке.
- **Зависимости**:
    - Доступ к API TikTok для данных видео.
    - Своевременный ежемесячный отчёт дистрибьютора с точным заработком по треку.
- **Изменения моделей данных / схемы**:
    - Новая таблица в базе для данных об использовании видео: ID автора, ID видео, ID трека, число просмотров и сумма выплаты.
    - Связка этих новых данных с отчётом дистрибьютора о выручке.
- **Бизнес-логика**:
    - Забирать данные видео (использованный трек, просмотры) из TikTok API.
    - Сопоставлять данные с отчётом дистрибьютора о выручке.
    - Считать выплату автора по числу просмотров и доле выручки дистрибьютора.
- **Изменения API**: новые эндпоинты для получения данных видео и просмотров, а также логика расчёта выплат.
- **UI/UX**: дашборд, где автор видит использование своих видео и детали выплат.
    - Вайрфреймы: экран дашборда со статистикой использования видео, суммой просмотров и деталями выплат за месяц.

### **c. План тестирования**

- **Юнит-тесты**: проверить точность данных из API TikTok и правильность расчёта выплат.
- **Интеграционные тесты**: проверить связку данных TikTok API с отчётами дистрибьютора и системой выплат.
- **QA**: ручное тестирование, чтобы убедиться в точности выплат и правильном потоке данных.

### **d. План мониторинга и алертов**

- **Логирование**: логировать каждый случай использования музыки и расчёта выплаты для аудита.
- **Мониторинг**: использовать инструменты мониторинга, чтобы система обрабатывала данные правильно и вызовы API проходили успешно.
- **Метрики**: следить за числом обработанных видео, посчитанных просмотров и сделанных выплат.
- **Алерты**: ставить алерты на неуспешные вызовы API или расхождения в расчёте выплат.

### **e. План релиза / раскатки и деплоя**

- **Среды**: development для тестов, staging для UAT, production для боевого запуска.
- **Поэтапная раскатка**: постепенная раскатка через feature flags, чтобы интеграция прошла гладко.
- **Коммуникация**: рассказать авторам об автоматической системе выплат и как смотреть заработок в дашборде.

### **f. План отката**

- **Риски ответственности**: неточные выплаты при расхождении данных или сбое API.
- **Смягчение**: ручные запасные процедуры, чтобы проверить и исправить расхождения в выплатах.
- **Не задеть другие компоненты**: деплоить в изолированных тестовых средах.
